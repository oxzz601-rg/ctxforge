# ctxforge

**Give your model the right files, not the whole repository.**

Every LLM coding session starts the same way: which files do I paste? Dump everything and you pay for noise, lose the signal and blow the context window. `ctxforge` scores a repository against your question, packs the best files into a token budget, and prints one deterministic markdown bundle you can drop straight into a prompt.

```bash
ctxforge . -q "add retry with backoff to the billing client" -b 30000 -o context.md
```

```
wrote context.md: 9 file(s), 28714 of 30000 tokens
```

## Install

```bash
python -m pip install -e .
```

Python 3.9+, no dependencies, no network calls.

## What it does

1. **Walks** the repo, skipping `.git`, `node_modules`, virtualenvs, build output, binaries and oversized files.
2. **Ranks** every file with BM25 over your query, blended with structural signals: a query hit in the path is strong, `README`, manifests and entrypoints get a lift, tests get a small penalty.
3. **Follows imports** one or two hops so the module your best match imports comes along instead of being silently missing.
4. **Packs** the ranking into the budget, truncating a single huge file (head and tail kept, the middle marked) instead of letting it eat everything.
5. **Renders** a repository map plus fenced, language-tagged file bodies, sorted by path so the output is byte-stable between runs.

The bundle starts with metadata your model can use:

```markdown
# Context bundle: add retry with backoff to the billing client

9 file(s), 28714 tokens of a 30000 token budget. Generated by ctxforge.

## Repository map
- `README.md` (210 tokens)
- `src/billing.py` (512 tokens)
...
```

## Inspecting the choice

```bash
ctxforge . -q "retry billing" --list
```

```
   14.71      512  src/billing.py
    3.28      180  src/db.py
    1.05      210  README.md
```

`--json` prints the same information as a manifest, which is handy for scripting:

```bash
ctxforge . -q "retry billing" --json | jq '.files[] | {path, tokens}'
```

## Useful flags

| flag | meaning |
| --- | --- |
| `-q, --query` | what the context is for; omit it for a repo overview |
| `-b, --budget` | token budget (default 60000) |
| `--max-file-tokens` | per-file cap, default 8000 |
| `--include` / `--exclude` | globs, repeatable, e.g. `--include "src/*"` |
| `--no-import-boost` | rank purely on text match |
| `-o, --output` | write to a file instead of stdout |
| `--list` / `--json` | inspect the selection without emitting the bundle |

## Token estimates

`ctxforge` counts words and punctuation, which tracks BPE tokenizers closely enough for budgeting and errs on the high side. It is deliberately tokenizer-agnostic: no model-specific vocabulary, no downloads. If you need exact numbers for a specific model, keep your budget a little under the real limit.

## Using it in a workflow

```bash
# hand the bundle to any CLI model
ctxforge . -q "why does login fail after deploy" -b 40000 -o ctx.md
cat ctx.md | llm -m gpt-4o-mini "Find the likely cause and propose a fix"

# or make it part of a review loop
ctxforge . -q "$PR_TITLE" -b 60000 -o context.md
```

Because the output is stable for a given commit and query, bundles can be cached, diffed or attached to an issue.

## Tests
